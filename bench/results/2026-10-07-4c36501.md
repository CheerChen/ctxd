## Findings

- **Daily scenarios are network-bound and flat.** Slack, Jira and GitHub make the
  same requests in both refs; wall differences sit inside run-to-run spread
  (S1's HEAD runs span 1.59–3.10 s with identical code paths).
- **One real regression: Confluence single page to stdout, +0.2 s (C1 / C1x).**
  The attachment list adds one attachments call (5 → 6 requests), run serially
  after the metadata lookups. It could overlap with the comment fetches.
- **Larger numbers elsewhere are work that 0.6.0 skipped.** C3 / C3p now
  download the attachments (7 KB → 3.4 MB, 1 KB → 4.2 MB). C5 / C6 now export
  the whole tree (18 → 52 and 54 → 213 pages). Per page, C6 costs 0.21 s on
  HEAD vs 0.19 s on 0.6.0.
- **C4 makes 22 more requests and writes 1.4 MB more** on a tree only two
  levels deep, so depth is not the cause; the pagination fix (collections
  over 100 items) is the likely one. Not confirmed: the per-run raw data of
  this A/B run was overwritten by the sweep (fixed in bench.py since).
- **Concurrency scales near-linearly to 12 with no 429 / retry / 4xx**:
  C5 57.6 s (c=1) → 12.8 s (c=5, default) → 6.8 s (c=12); peak RSS 47 → 66 MB.
- **Worth a look next:** J3 spends ~1.4 s per expanded child (cross-source
  recursion looks serial); S3 takes 9 s for 9 requests / 5.4 MB of Slack file
  downloads; G3 writes 40 KB for a 10.6k-line diff (diff mode or API cap,
  not checked).
